# sdd-scaffold — 把一句想法，变成一个**规格先行、可追溯、可交接**的项目

> 让 AI 帮你做项目，通常会得到一次性的代码倾倒：没边界、没决策记录、改需求时无从下手。
> **sdd-scaffold** 把 SDD 范式固化成一个可执行的技能流程——先调研、再对话分析、后落地，规格先行、门禁推进、文件即状态。

```
需求分析 → 方案设计 → 构建 → 测试 → 上线
```

---

## 为什么需要它

| 直接让 AI 做项目 | 用 sdd-scaffold |
|---|---|
| 一次性倒出大段代码，需求没边界 | 先竞品调研 + 对话式深挖，规格先行 |
| 改个功能不知道动了哪 | 功能（Fxx）/ 异常（Exx）/ 接口 / 任务四层互引编号 |
| 技术选型拍脑袋，事后说不清 | 选型写 ADR，架构变动先算"优势与代价"再确认 |
| 会话一断，上下文全丢 | 全部状态落盘 `.agent/`，新会话秒恢复 |
| 需求越改越乱，没人负责 | 阶段门禁由**你**主动宣布，AI 不抢跑 |

---

## 它是怎么做的

**前置调研** — 需求分析前先检索 GitHub / 互联网上的同类竞品，结论写入 spec.md「竞品参考」，不闭门造车。

**前两阶段纯对话式** — 需求分析与方案设计通过自然语言多轮对话推进，不弹选项卡片；需求分析是最值得投入时间的阶段，宁可多问，不可含糊。

**阶段门禁由你说了算** — 必须你主动回答"需求分析阶段结束，进入方案设计"（方案设计同理）才推进，AI 不替你判断阶段结束。

**设计变动先算账** — 任何架构/设计变动，AI 必须先在对话中分析优势与代价，你确认后才执行。

**后续走 SDD** — 任务拆解 → 逐任务构建 → 测试与上线，按门禁推进、文件即状态。

---

## 适合 / 不适合

- **适合**：单人或小团队、MVP 功能 3-8 条的中小项目；想让 AI 交付**可追溯、可交接**的项目
- **不适合**：超大型项目（建议先拆模块逐个搭建）；一次性的小脚本（直接写更快）

## 30 秒上手

安装（克隆到所用 Agent 的技能目录，支持 ZCode / Claude Code 等兼容 SKILL.md 的 Agent）：

```bash
# ZCode
git clone https://github.com/Soleil1043/sdd-scaffold.git ~/.agents/skills/sdd-scaffold
# Claude Code
git clone https://github.com/Soleil1043/sdd-scaffold.git ~/.claude/skills/sdd-scaffold
```

然后在目标目录新开会话：

```
/sdd-scaffold 帮我做一个记账 CLI 工具
```

或直接说"新建项目""搭个脚手架""帮我把这个想法做成项目"。

**你会经历**：

1. AI 先调研 2-4 个同类竞品，告诉你可借鉴什么
2. 进入需求分析对话——多轮追问，直到需求足够清晰
3. 你主动说"需求分析结束，进入方案设计"，才进入下一步
4. 方案设计同样对话式；技术栈、架构都在讨论中确定
5. 落地文件 → 任务拆解 → 逐任务构建 → 测试 → 上线，每步都有门禁

## 产物一览

```
your-project/
├── AGENTS.md              ← 项目规则（技术栈、工作流约束、Git 规范）
├── README.md              ← 现场生成，非模板复制品
├── .cursor/rules/main.mdc ← 按 harness 生成的规则文件（TRAE/Claude/Cursor/Windsurf/Cline）
└── .agent/
    ├── spec.md            ← Phase 1：需求规格说明书（竞品参考 + Fxx 功能 + Exx 异常 + 变更记录）
    ├── plan.md            ← Phase 2：设计说明书（选型含代价 + 表结构 + API + 决策）
    ├── tasks.md           ← Phase 3：任务清单（依赖 + 验收 + 覆盖标注）
    ├── progress.md        ← Phase 4：逐任务构建日志
    ├── decisions.md       ← 全程：决策记录（D0XX，ADR 格式）
    └── prompts.md         ← 各阶段 / 需求变更 / 设计变更 / 回退 / 上下文恢复提示词
```

每个 `.agent/*.md` 对应标准流程的一步，**文件即状态**。

## 常见疑问

**Q：可以只跑需求分析、不落地代码吗？**
可以，任何阶段都能停。后续新会话用「上下文恢复 Prompt」从断点继续。

**Q：已有 `.agent/` 目录会被覆盖吗？**
不会。检测到已有 `.agent/` 时自动转**恢复模式**，读取现有状态并报告，绝不覆盖。

**Q：支持哪些 Agent / 编辑器？**
TRAE、ZCode、Claude Code、Cursor、Windsurf、Cline，以及任何兼容 SKILL.md 规范的编码 Agent。模板以 AGENTS.md 为单一源，按 harness 生成对应规则文件。

**Q：技术栈被锁死了吗？**
没有。技术栈在方案设计阶段对话确定，模板不锁任何栈；用户指定的栈完全尊重。

## 设计说明

- 模板以**资产快照**形式打包在 `assets/template/`，通过初始化脚本（`scripts/init.sh` / `init.ps1`，幂等、绝不覆盖已有文件）确定性复制，保证每次产出一致；`SKILL.md` 只做编排，细节规则在被复制进项目后才按阶段加载
- 工作流约束来自 vibecoding-scaffold 五阶段范式
